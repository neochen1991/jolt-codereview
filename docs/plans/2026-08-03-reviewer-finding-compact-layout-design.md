# Reviewer 检视问题紧凑布局设计

## 目标

在不减少原有业务字段的前提下，降低普通 reviewer 检视问题列表的视觉密度，并确保超长问题描述能够被明确地完整查看。

## 布局

每条问题使用紧凑的三层结构：

1. 操作层：复选框、严重级别、提交状态、置信度和“标误报”。
2. 定位层：文件路径、行号和问题标题。
3. 描述层：默认最多显示三行；仅在内容实际溢出时展示“展开全文”，展开后显示完整描述并允许收起。

点击卡片仍打开原有问题详情弹窗。管理员可见的 Agent 与来源标签继续遵循现有权限逻辑，不为 reviewer 增加新字段。

## 交互与无障碍

- 展开/收起按钮阻止卡片点击事件，避免误开详情弹窗。
- 按钮通过 `aria-expanded` 表达当前状态。
- 文件路径和标题允许换行，避免挤压行号和操作按钮。
- 窄屏下操作层自动换行，正文保持完整可读。

## 验证

- 静态回归验证紧凑结构、三行折叠和展开按钮存在。
- 前端类型检查和生产构建通过。
- 使用普通 reviewer 在真实 24 条问题 MR 上验证：默认卡片高度明显下降，展开后正文无裁剪，调试信息仍不可见。
